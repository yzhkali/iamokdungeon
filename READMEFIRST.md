# README FIRST - I’m OK Dungeon / 没事地下城

> 如果你是新的 Codex 对话，先读这个文件。这个项目的所有内容后续都保存在本文件夹：`D:\I’m OK Dungeon`。

## 项目一句话

《没事地下城》/ **I’m OK Dungeon** 是一个复古像素风 ARPG / 轻肉鸽游戏：玩家进入由“中国式亲密关系”和中文互联网梗构成的地下城，和“没事”“随便”“你猜”“呵呵”等阴阳怪气词怪战斗，最终面对现实婚恋压力具象化的 Boss。

- 当前主入口：`prototype/3d/index.html`
- 本地运行：`npm run serve`
- 本地验证：`npm run validate`、`npm run check:browser`、`npm run prepush`

- 完整第三方 vendor 源包不再入库，只保留 `prototype/3d/assets/vendor/` 运行子集，来源见 `prototype/3d/assets/vendor/NOTICE.md`。

## 核心方向

- 画面气质参考《Sea of Stars》的复古像素精致感，但第一阶段不能追求同等体量。
- 玩法参考俯视角 ARPG + 轻弹幕 + AOE 躲避 + 肉鸽技能三选一。
- 场景体量可以参考《Hades II》早期单个战斗房间的大小，但第一版要显著缩小。
- 怪物不做传统怪物，直接把阴阳怪气词语/互联网关系梗实体化。
- 整体不是“骂女性”或性别对立，而是讽刺中文互联网亲密关系、家庭压力、婚恋谈判和沟通失败。

## 玩家角色设想

开场可以选择不同人格/流派，每个角色对应不同基础属性和技能倾向：

- 老实人：血厚、稳定、技能偏真诚/防御。
- 渣男：位移多、爆发高，但技能可能有反噬或可信度惩罚。
- 舔狗：回血强、护盾多、输出低，容易被消耗。
- 龟龟：防御极高、行动慢，靠反伤和苟活。

后续可以继续扩展，但第一版建议只做 1 个角色，验证核心手感。

## 怪物设想

词语/梗作为怪物本体，给它们设计移动、动作、攻击范围和前摇。

示例：

- 呵呵：近战突刺，命中后减速或造成沉默。
- 随便：原地旋转，向四周发散弹幕。
- 你猜：在玩家脚下生成延迟 AOE。
- 我没事：假装无害，靠近后爆炸。
- 你忙吧：从屏幕边缘制造横向弹幕墙。
- 挺好的：受击后分裂成多个小词。

## 技能设想

打完房间后学习技能，像肉鸽奖励一样三选一。技能名来自中文互联网恋爱/沟通语境，说明则落实为攻击力、范围、冷却、特效。

示例：

- 多喝热水：治疗或范围恢复，也可能激怒某些 Boss。
- 好久不见：远程穿透攻击，附带尴尬沉默。
- 想你了：追踪弹，但连续使用会降低可信度。
- 我错了：短暂无敌或清弹幕。
- 你说得对：格挡并反弹下一次攻击。
- 买了奶茶：强力回血，冷却长。

整体风格要阴阳怪气、搞笑，不追求华丽特效。

## Boss 设想

Boss 应该是亲密关系/现实压力的具象化，而不是单纯攻击某个性别。

已提到的 Boss：

- 大姨妈：周期性情绪风暴 Boss，机制可做阶段变化、范围伤害、节奏失控。
- 扶弟魔：建议改造成“原生家庭压力”或“亲戚资源吸血”类 Boss，召唤亲戚弹幕、转移仇恨、资源吸血。
- 彩礼：最终 Boss。代表现实婚恋系统压力、家庭谈判、房车存款、面子、承诺和恐惧。

“彩礼”Boss 可刷屏台词：

- 你爱不爱她？
- 你有房吗？
- 别人家都这样。
- 这不是钱的问题。
- 这是态度问题。

## 第一阶段范围控制

不要一上来做完整游戏。建议先做 7 天左右的核心原型。

第一版最小可玩目标：

- 1 个战斗房间。
- 1 个可操作角色。
- 3-6 种词怪。
- 1 个 Boss：建议先做“没事”。
- 玩家可移动、普攻、闪避。
- 怪物有近战、远程弹幕、AOE 预警和爆炸。
- 玩家能受伤、死亡；怪物和 Boss 能被打死。
- 战斗结束后出现 1 次技能三选一或结算页面。

第一版不要做：

- 多角色完整平衡。
- 大地图。
- 装备系统。
- 剧情长线。
- 多个 Boss。
- Sea of Stars 级别的精致像素资产。

## 推荐开发路线

阶段 0：项目整理

- 在 `D:\I’m OK Dungeon` 下建立项目结构。
- 保存设定、策划、原型、素材、导出文件。

阶段 1：灰盒战斗原型

- 先用简单几何图形或粗像素占位。
- 实现移动、攻击、闪避、碰撞、血条。
- 实现一种近战怪、一种远程怪、一种 AOE 怪。
- 实现 Boss “没事”的基础招式。

阶段 2：梗和手感

- 把怪物名字、技能名、攻击提示、受击反馈写得好笑。
- 调整移动速度、攻击距离、闪避无敌帧、弹幕速度、AOE 延迟。
- 目标是即使没有正式美术，玩起来也能让人笑并愿意再试。

阶段 3：像素视觉竖切

- 统一像素风格。
- 制作 1 个角色、1 个房间、数种词怪、1 个 Boss 的基础动画。
- 增加音效和 UI。

阶段 4：扩展 Demo

- 扩到 4-5 个战斗房间。
- 加入 2-4 个可选角色。
- 加入 10-20 个技能。
- 加入多个 Boss 和基础肉鸽流程。

## 图片生成流程（重要）

本项目后续生图不要默认寻找内置 `image_gen`，也不要直连 `https://api.openai.com/v1/images/generations`。

必须使用 Codex 自定义 API 配置：

1. 从 `C:\Users\Windows\.codex\config.toml` 读取当前 `model_provider`。
2. 在对应 `[model_providers.<name>]` 中读取 `base_url`。
3. 请求 `{base_url}/v1/images/generations`。
4. 从 `C:\Users\Windows\.codex\auth.json` 读取 `OPENAI_API_KEY`，只用于请求头，绝对不要打印或写入文件。
5. 响应图片在 `response.data[0].b64_json`，需要 base64 解码保存为 PNG。
6. 图片和提示词都保存到项目目录下对应 `assets/` 子目录。

详细流程见：

- `D:\I’m OK Dungeon\docs\image_generation_workflow_v0.md`
